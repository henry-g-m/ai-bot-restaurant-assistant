= Authentication =

Its azure/login step passes only client-id, tenant-id and subscription-id, with no client secret, which only
works over OIDC. DEPLOYMENT.md even notes clientSecret (not needed, using OIDC instead in modern setup).

OIDC is the more secure option and is what Microsoft and GitHub now recommend. Consistency with your other repos is a fair reason to prefer a secret, though, especially for a demo.
If you'd rather use a client secret, the switch is small:
 1. Create a client secret on github-actions-container-apps and store it as a GitHub secret, AZURE_CLIENT_SECRET.
 2. In deploy.yml, give azure/login the secret via creds, replace ARM_USE_OIDC: true with ARM_CLIENT_SECRET: ${{ secrets.AZURE_CLIENT_SECRET }}, and drop the id-token: write permission.
 3. You won't need the federated credential.
